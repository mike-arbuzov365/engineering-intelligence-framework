## Knowledge Delta

- **New operational lesson**: `sync_package_sources.py` writes files to disk, but hatchling's `packages = [...]` wheel-build mode (this project's `pyproject.toml`) selects files via VCS state, not just presence on disk - newly-synced resource files must be `git add`-ed (staged is sufficient; a full commit is not required) before `python -m build`/`test_package_build.py` will include them. A sync with no corresponding `git add` will pass `sync_package_sources.py --check` while silently producing a wheel missing the new files - `test_package_build.py` is the check that catches this, `--check` alone does not.
- **General lesson, reinforced three times this session**: adding a new `BUNDLE_TREES` entry is not a one-file change. It touched `eif_init.py` (the source of truth), `sync_package_sources.py`'s `RESOURCE_TREES` (a second, independent list - imports `BUNDLE_SCRIPTS` from `eif_init.py` already, but keeps its own separate `RESOURCE_TREES`), and `test_journey.py`'s three hardcoded copytree blocks (a third, fully independent list with no shared source at all). Only the full `run_all.py --json` run caught the third one - `smoke.py` and the targeted per-file test runs used throughout this session do not touch `test_journey.py`. Worth running the full suite at least once per session that touches a cross-cutting list like this, not only at final packet closeout.
- **Confirmed pattern, now twice**: an unconditional assumption ("knowledge is always EIF-managed") existed in TWO places independently (the generator in `eif_init.py` and the drift-checker in `eif_verify_runtime.py`) - fixing only the generator would have left the doctor falsely flagging a correctly-unmanaged instance as drifted. When fixing a "block always assumes X" bug, check for the same assumption in whatever independently re-derives or re-checks that block's content, not just the place that renders it.
- `str.format()` does not recursively format a value substituted into an outer template - a value containing its own `{placeholder}` syntax must be pre-formatted before use as a substitution value. Worth a general callout given this codebase renders several nested templates this way.
