# Governance

## Current phase

Engineering Intelligence Framework is at **v0.1.0, single-maintainer**
phase. It is extracted from a private production instance (referred to as
an "instance" throughout the docs) maintained by one owner. This document
describes governance as it exists today and how it is expected to evolve
as the project takes contributors.

## Decision making at 0.x

- The maintainer makes all decisions on scope, architecture, naming,
  licensing, and release timing.
- Decisions with lasting methodology impact are recorded as ADRs or
  decision records once the project structure supports them (see
  `core/policies/`).
- There is no public roadmap vote or RFC process yet - see
  [`docs/architecture/HOW-EIF-WORKS.md`](docs/architecture/HOW-EIF-WORKS.md#roadmap)
  for the current direction.

## After 0.1

The project intends to move toward:

- A documented RFC process for framework-level (not project-instance-level)
  changes.
- Maintainer additions based on sustained, high-quality contribution.
- A public roadmap reviewed on a regular cadence.

This section will be updated with concrete criteria once the project has
external contributors to govern.

## Reporting concerns

- Code of conduct violations: see [`CODE_OF_CONDUCT.md`](CODE_OF_CONDUCT.md).
- Security or privacy issues: see [`SECURITY.md`](SECURITY.md).
- Everything else: open a GitHub issue once the repository is public.
