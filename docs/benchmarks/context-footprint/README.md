# Static context footprint

This is a model-free byte measurement, not a token-cost or quality benchmark.
The script creates disposable `synthetic-demo` instances for all four adapters.
It counts the entrypoint, loader frontmatter, one doctor response and a one-hop
walk of relative Markdown links from each scenario's skill. It never reads a
private instance. Doctor output replaces the temporary instance root with `.`;
UTF-8 is forced and timing is omitted. These normalizations make repeated runs
comparable. Token estimates are `ceil(bytes / 4)`, not tokenizer counts.

```text
python scripts/eif_context_footprint.py --no-latency --out measurement.json
python scripts/eif_context_footprint.py --no-latency --check docs/benchmarks/context-footprint/baseline.json
python scripts/tests/test_context_footprint.py
```

[baseline.json](baseline.json) records the source SHA and measured components.
`--check` compares all measured components and ignores provenance notes. B0 is
the pre-implementation source; later intentional policy changes require a new
measurement, never silently replacing B0. Temporary-path normalization means
doctor byte counts differ from the unnormalized planning measurement.

Scenarios: `light` adds only doctor; `knowledge_search`, `packet_plan` and
`packet_run` add their respective skill walk. A separate scenario counts full
loader files in case the host loads more than frontmatter. Runtime bundle size
is reported separately and is not automatically loaded context.

Budgets: reader `tools/list` 6,144 bytes; response 24,576 bytes; brief target
1,536 and hard limit 4,096 bytes; default artifact page 4,000 characters.
A compact entrypoint may ship only after the packet scenario comparison passes
the 15% threshold using actual protocol response sizes. Host schema loading,
deeper policy reads and behavioral quality remain unmeasured. No savings claim
follows from this static measurement.

## Phase-one gate

[gates.json](gates.json) records G1 and branch B.
[precompact.json](precompact.json) includes the full reader catalog, a brief,
outline discovery and every page of two frozen startup sections for each
packet scenario. Section choice was fixed before byte measurement, according
to startup relevance rather than response size. This samples startup reads,
not every policy read in an entire task.

The 2,400-byte compact entrypoint remains an **INFERRED budget** in this
measurement; SESSION-007 must replace it with actual generated bytes. The
unchanged entrypoint plus MCP can increase light startup bytes by over15%;
adding the reader alone does not shorten an existing entrypoint. No runtime
token-cost or quality conclusion is established. `--mcp-after --check`
compares current measurements against the chosen recorded result. Historical
B0 must be reproduced from its recorded source state; intentional later
changes are not silently folded back into that baseline.

## Actual compact startup measurement

[after.json](after.json) replaces the candidate block budget with actual
generated entrypoints (including each adapter wrapper). All four scenarios
include full tools/list loading and duplicated response content. Reproduce:

```text
python scripts/eif_context_footprint.py --mcp-after --no-latency --check docs/benchmarks/context-footprint/after.json
```

| Adapter | Entrypoint bytes | light B0 / after | knowledge_search B0 / after | packet_plan B0 / after | packet_run B0 / after |
|---|---:|---:|---:|---:|---:|
| claude-code | 2033 | 11931 / 10961 | 16318 / 17889 | 27095 / 20394 | 27881 / 19100 |
| codex | 2033 | 11925 / 10961 | 16312 / 17889 | 27089 / 20394 | 27875 / 19100 |
| cursor | 2282 | 12221 / 11210 | 16608 / 18138 | 27385 / 20643 | 28171 / 19349 |
| hermes | 2034 | 11929 / 10962 | 16316 / 17890 | 27093 / 20395 | 27879 / 19101 |

G1c passes for both packet scenarios on every adapter. Light is about8%
smaller in this bounded byte model; knowledge-search startup is about10%
larger. The reader alone with an unchanged legacy entrypoint can increase
light bytes by over15%. These are startup **byte** comparisons, not token
counts, billing, complete-task reads or matched quality results.
The comparison counts outline discovery and every page of the frozen relevant
sections; later reads remain outside this scenario. The source-tree digest is
recorded with each measurement. The original B0 and precompact records remain
historical inputs, not silently rewritten after implementation.
