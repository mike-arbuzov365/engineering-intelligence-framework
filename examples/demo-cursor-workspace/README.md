## 6. Clean removal on adapter switch

Continuing in the same illustration directory, switching away from Cursor
(`--force --adapter claude-code`) deletes the dedicated Cursor file outright
(it is exclusively EIF-owned - nothing legitimate to preserve) while the
sibling rule is still never touched:

```
python scripts/eif_init.py --framework-root . --instance-path examples/demo-cursor-workspace/coexist-illustration --force --adapter claude-code
```

```text
...
create CLAUDE.md (EIF-managed block)
Generated agent instructions at <path>/coexist-illustration/CLAUDE.md
deleted old entrypoint .cursor/rules/eif/governance.mdc (adapter switch 'cursor' -> 'claude-code')
update-block .gitignore (EIF-managed block)
...
EIF instance initialized at <path>/coexist-illustration
```

`.cursor/rules/team-style.mdc` still exists, still byte-identical; only the
now-empty `.cursor/rules/eif/` directory is left behind (harmless - a
directory this run did not create is never removed, by design; see
`scripts/tests/test_cursor_adapter.py` scenarios 2/2b for the fault-injected
proof that a *pre-existing* sibling directory is never removed even on
failure). Fault-injected rollback (a crash forced immediately after the old
entrypoint's removal commits, restoring it byte-for-byte) is proven in the
same suite, scenario 19 - not reproduced here since it requires an
environment variable fault-injection hook, not a plain CLI invocation.

## A real bug found and fixed while building this adapter

The first version of `entry_strategy: "full-regen"` unconditionally
overwrote whatever already existed at `.cursor/rules/eif/governance.mdc`,
with no check for prior EIF ownership - a real, if narrow, data-loss risk
(a foreign file coincidentally at that exact path would have been silently
replaced). Fixed before this adapter's PR was reviewed: full-regen now
requires proof of ownership (a single well-formed EIF block) before
touching anything already there, and STOPs otherwise - regardless of
adoption mode, file size, or content heuristics. See
`scripts/tests/test_cursor_adapter.py` scenario 13 for the executable proof,
both under coexist and under an explicit greenfield override.
