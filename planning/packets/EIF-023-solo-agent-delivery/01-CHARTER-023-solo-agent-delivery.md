# Керована розробка для одного власника

## Мета

Соло-розробник доручає агенту коротку правку або повний пакет. Обсяг підготовки відповідає ризику. Перед зміною агент знаходить релевантне проєктне знання. Оркестратор послідовно приймає саме ту версію роботи, яку перевірив. Новий чат може продовжити роботу за файлами.

## Межі

У фреймворку доробити правила, вихідні навички, шаблони, спільні операції CLI/MCP та синтетичні приклади. Вебчастину постачати через програмний профіль як необов’язкове доповнення. Приватні проєкти дали вихідні спостереження. Їхні дані, навички, конфігурації й журнали залишаються в проєктах. Пілот у реальному проєкті використовує окремо виділену робочу копію за дорученням власника. Публічний реліз, оплата запусків, розгортання, загальний запис через MCP та зміна налаштувань клієнта мають окремі повноваження.

## Критерії приймання

| ID | Спостережуваний результат | Сесія |
|---|---|---|
| A1 | Легка дія обходиться без планового файлу. Для задачі на одну сесію є один файл плану. Два залежні кроки та коротка несумісна зміна одержують відповідно компактну і розгорнуту підготовку | 001, 006 |
| A2 | Для зачеплених навичок узгоджено канонічний посібник, контракт і встановлену точку входу. Існують позитивний і негативний сценарії. Причини помилок старих проєктних контрактів розрізнені | 001, 006 |
| A3 | Пошук правильно розрізняє керовану й зовнішню пам’ять, нуль результатів та неповне покриття. Запис сесії дає змогу перевірити пошук, його вплив і долю сталого висновку | 002, 006 |
| A4 | Для окремої сесії тестів є незалежний критерій, правильна причина очікуваної невдачі та позитивний контроль. Легкі зміни обходяться без додаткової сесії | 001, 003, 004 |
| A5 | Для оркестрованого пакета визначені спроба, ревізія, рішення й причини блокування. Старе `next_session` зберігає свій зміст. CLI та MCP однаково пояснюють допуск. Закриття чату не скасовує повернення роботи | 003, 004, 006 |
| A6 | Для вебзміни критерій веде до стану екрана, наявного компонента і перевірки. Суто серверна зміна не породжує дизайн-документи | 005, 006 |
| A7 | Збірка з чистої копії відтворює читання. Завершення stdio на Windows перевірено окремо. Дані звичайних програм, фактичні модельні запуски та невиконані перевірки позначено окремо | 006 |

Завершення методики, програмної реалізації, живого пілота і публікації фіксувати окремо. Обмежений бюджет або відсутність клієнта залишає конкретний критерій відкритим.
