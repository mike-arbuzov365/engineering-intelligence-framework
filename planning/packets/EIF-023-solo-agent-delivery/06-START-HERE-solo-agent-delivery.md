# Вхід для оркестратора

Передаючи сесію новому чату, дай йому посилання на її файл запуску. У розділі «Підстава для рішення» виконавець знайде причину зміни, відповідний фрагмент [аналітичного звіту](../../2026-11-21-eif-sdd-review.uk.md) та першоджерела на перевірених ревізіях. Звіт пояснює задум власника й підстави рекомендацій. Поточний стан реалізації звіряй із кодом і відтворюваною перевіркою.

Власник доручив виконати пакет 21.11.2026. Усі сесії працюють послідовно в одній гілці та одній робочій копії. Для пакета передбачено один PR. Автор незалежних тестів і виконавець перевірки відновлення отримують окремий контекст. Оркестратор приймає кожну сесію.

1. Прочитай [мету й критерії](01-CHARTER-023-solo-agent-delivery.md), [факти та перенесені питання](02-FACTS-023-solo-agent-delivery.md), [рішення](03-DECISIONS-023-solo-agent-delivery.md), [дорожню карту](04-ROADMAP-023-solo-agent-delivery.md) і [самоперевірку](05-SELF-REVIEW-023-solo-agent-delivery.md). [Огляд](../../2026-11-21-eif-sdd-review.uk.md) містить першоджерела. Попередній чат для початку роботи не потрібний.
2. Звір поточні `origin/main`, поточний реліз і стан робочого дерева. Цей пакет підготовлено окремо від чистої бази реалізації. Використай актуальну інтеграційну базу в окремій робочій копії, забезпеч доступність погодженої версії пакета й огляду. Залиши на місці роботу на початковій гілці. Перевір конфлікти із новішими пакетами та рішеннями.
3. До першої зміни визнач належне джерело знань для цільового проєкту. У репозиторії самого фреймворку під час планування були приклади конфігурацій; використано реєстр рішень, посібники і попередній пакет EIF-022. Підключений до іншого інстансу MCP не представляє пам’ять цього репозиторію.
4. Запускай сесії 001–006 послідовно. До появи перевіреного нового режиму відповідальний оркестратор веде рішення за поточними правилами EIF; новий спосіб делегування відтворюй у підготовленій фікстурі або в явно погодженому проєктному режимі. Для кожної спроби запиши предмет перевірки, версію і причину приймання чи повернення. Пропущений критерій блокує залежну сесію.
5. Контрольна точка зберігає поточну дію, докази та наступний крок. На переході між чатами перевір її та джерела. Дій у межах [рішень](03-DECISIONS-023-solo-agent-delivery.md). За відсутності модельного бюджету чи потрібного хоста заверши незалежні локальні перевірки й зафіксуй, що лишилося.
6. Для незалежного огляду без історії чату попроси рецензента за файлами визначити різницю між роботою без пакета й компактним пакетом, знайти умову для окремої сесії тестів, назвати джерело зовнішньої пам’яті та пояснити, чому повернена версія блокує наступну сесію. Порівняй відповіді з A1–A7, посиланнями і фактичними командами. Закрий пакет через [підсумок](07-CLOSEOUT-023-solo-agent-delivery.md).
