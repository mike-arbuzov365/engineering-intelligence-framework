# Вибір сховища і передача знань

**Мета.** Виправити обробку зовнішньої пам’яті та встановити перевірний порядок читання, запису й відновлення для структурованих задач. Критерії статуту — A3.

## Підстава для рішення

На перевіреному зовнішньому сховищі пошук застосував схему EIF і повернув нуль проіндексованих документів. Почни з перевірки `knowledge.managed` та правила пошуку самого проєкту. Якщо новіша версія вже розрізняє сховища, відтвори обидва випадки й зосередь зміни на прогалині, яка залишилась.

У звіті — [Що перевірено у двох проєктах](../../../2026-11-21-eif-sdd-review.uk.md#9-що-справді-відбувається-з-проєктною-памяттю).

Першоджерела — [Правила для керованої і зовнішньої пам’яті](https://github.com/mike-arbuzov365/engineering-intelligence-framework/blob/4e7e5d62ddb7d5b6c9723897eb30f9d2e824e104/scripts/eif_init.py) · [Реалізація пошуку в перевіреній версії](https://github.com/mike-arbuzov365/engineering-intelligence-framework/blob/4e7e5d62ddb7d5b6c9723897eb30f9d2e824e104/src/engineering_intelligence_framework/service/operations.py).

## Перед першою зміною

Прочитай [рішення](../03-DECISIONS-023-solo-agent-delivery.md) та записи за попередньою спробою. Звір актуальну базу й зачеплені матеріали: `scripts/eif_init.py`, `playbooks/knowledge-search.md`, `playbooks/knowledge-ingest.md`, `playbooks/session-closeout.md`, `templates/`, `src/engineering_intelligence_framework/service/operations.py`. У налаштованому сховищі знайди попередні рішення за темою цієї сесії; запиши в завданні або контрольній точці джерело, результат і вплив. Якщо інстанс не управляє пам’яттю, використовуй правило його власника. У репозиторії фреймворку почни з реєстру рішень.

## Обсяг

У спільній операції визначати режим до застосування схеми EIF. Для зовнішнього сховища повернути обмежений опис способу читання за правилами проєкту. Якщо засіб недоступний, вказати межу покриття. Для керованого сховища зберегти фільтри життєвого циклу й повноту покриття. У наявному документі задачі перед змінами фіксувати запит/ідентифікатор джерела і вплив. У контрольній точці фіксувати нову невдалу спробу чи рішення, при закритті звіряти, що належить пам’яті. На відновленні звірити джерело ще раз, якщо воно змінилося. Передбачити старі записи без додаткових полів.

Зовнішнє сховище не переіндексовувати EIF і не оголошувати його документи пошкодженими через іншу схему. Не створювати примусовий журнал легкої задачі.

## Перевірка

Запускати з кореня чистої копії з відповідними встановленими залежностями та вихідним кодом цієї ревізії. На додачу відтворити критерій нижче на відповідній фікстурі. Для нової поведінки записати точну команду нового прикладу в поверненні.

```text
python scripts/tests/test_search_knowledge.py
python scripts/tests/test_generate_index.py
python scripts/tests/test_knowledge_delta.py
python scripts/tests/test_eif_mcp_inmemory.py
```

## Вихід і передача

- [ ] Приклад керованої пам’яті дає збіг; зовнішня веде до свого засобу пошуку; відсутнє джерело, нуль збігів і часткове покриття різняться. Кандидат у знання має долю та джерело. У фікстурі T07-подібного випадку правильний висновок відсутній у запиті й присутній у пам’яті.
- [ ] Синтетичні дані і очікування для сліпого модельного випробування S006. Приклад закриття та відновлення після зміни джерела.

До трьох ітерацій за цією перевіркою, зовнішніх запусків за замовчуванням нуль. При повторі тієї самої причини або зміні контракту поверни оркестратору факти й наступне рішення. Перед переходом між чатами онови та перевір `.session-context/eif-023-session-002.md`. При закритті зафіксуй долю сталого висновку у Knowledge Delta або підставу для його відсутності.

## Запис приймання

Джерело EIF для цієї сесії — D-21 і D-22 у `core/policies/decisions.md` на базі прийнятої 001 (`6b1c63f)). Використано чинний запис задачі, контрольну точку та Knowledge Delta. Для відновлення потрібно звірити версію джерела або повторити вузький пошук і перевірити вплив нового результату. Наявні контрольні точки залишаються придатними.

Знеособлений приклад відновлення: запит `username normalization`, джерело `knowledge/username-lesson.md`, початкова позначка K17. Тест SDK записує джерело і його зміну на K18, повторний запит повертає той самий шлях та оновлений уривок. Для закриття стійкий урок має джерело `test`, стан `validated` і доступний пошуком. Тимчасова спроба належить контрольній точці. Підтверджений висновок цієї сесії записано в канонічних посібниках пошуку та внесення знань.

Оркестратор прийняв спробу 1. Чотири зазначені тестові команди дали 11/11, 12/12, 6/6 та 63/63. Додатково перевірено контрольні точки (18/18) та ліміт компактного входу для восьми комбінацій клієнта й режиму. Живе читання агентом перевіряється в 006.

Для сліпої 006 взяти вихідну папку `source/` з T07 і сценарій із регресією. У видимому завданні залишити очікувану поведінку й команду тесту. Знеособлений урок з `scripts/tests/fixtures/eif_mcp/username-lesson.md` покласти лише у пам'ять тестового інстансу. Окремо перевірити час читання, назване джерело, вплив уроку на вибір виправлення та шість тестів.
