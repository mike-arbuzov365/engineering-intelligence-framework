## Обсяг

Зібрати локальний wheel з позначеним походженням, встановити в ізольоване середовище й виконати stdio self-test; перевірити завершення дочірнього процесу на Windows та описаний запасний шлях для пов’язаного робочого дерева Git. На однаковій початковій ревізії перевірити легку дію, RЕD/GREEN для регресії, пакет із поверненням, зовнішній і керований пошук та перенесення уроку наступному чату. Поведінковий тест пам’яті повинен приховувати урок від тексту запиту. За наявності погодженого хоста/бюджету дати новому чату тільки відомі джерела й вимоги, порівняти файли/CLI з MCP; окремо оцінювати зміну методики. Зарахувати лише дійсно виконані сценарії.

Власник не доручав публікацію, зміну клієнтських налаштувань або зовнішні витрати. Відсутню живу перевірку позначити невиконаною, не виводити економію зі статичного розміру відповіді.

## Запис пілота

Джерело фреймворку — D-19, D-21, D-22 і D-24 та прийнята 005. Із чистого Git-експорту `600854a352998e03f572bdcee73c630c051cb22b` зібрано локальний wheel `0.2.8` із відбитком SHA-256 `20c3bb7b00110f3ec0e76bbdccb50152710898cc1fbbd7420d06adcb5b8f8c5d`. В ізольованому середовищі Windows із Python 3.13.15 та SDK 2.1.1 `eifctl mcp serve --instance-path . --self-test` повернув `pass`, дев’ять інструментів і стан `ok`.

GPT-6.2 Sol High отримав синтетичний запит без відомостей про попередню спробу. Початковий тест дав 3/6. Виконавець знайшов знеособлений запис K17, повідомив про нього та пояснив вибір правки до зміни коду. Єдина зміна у фікстурі — `src/username.py`. Ті самі тести дали 6/6, оркестратор повторив їх. Від коміту початкової фікстури до зафіксованої правки минуло 202 секунди разом із підготовкою. Новий запис пам’яті для цього прикладу не знадобився.

Той самий незалежний виконавець прочитав установлену матрицю, відтворив усі чотири маршрути й виправив напис у наявному файлі без створення нових файлів. За матеріалами окремого синтетичного пакета, CLI та MCP stdio він відновив `SESSION-001`, спробу 1, повернення `changes_requested`, незакритий AC-04 і дію `revise_and_resubmit`. Відлік від підготовки другої перевірки до отримання її результату дав близько 152 секунд разом зі звіркою оркестратора.

Для того самого контрольного стану джерела займали 1378 байтів, JSON CLI — 1654, відповідь MCP у транспорті — 3612. Програма порівняла спільні поля й отримала однаковий допуск. Перевірка `test_eif_mcp_git.py` підтвердила у справжньому пов’язаному робочому дереві відмову MCP із підказкою `eifctl session resume-audit`. Пряма команда успішно відновила контрольну точку.

Оркестратор прийняв локальну спробу. `test_eif_mcp_package.py` — 15/15 з перевіркою відсутності повідомлення про закритий канал. Перший запуск `pip` не підібрав закріплену версію SDK. Повтор із `PIP_NO_CACHE_DIR=1` та `PYTHONUTF8=1` встановив ту саму версію. `uv` також встановив цю версію для локального пілота. `test_eif_mcp_stdio.py` — 27/27, `test_eif_mcp_git.py` — 111/111, `test_skill_eval.py` — 11/11.

Локальні перевірки завершують синтетичний пілот. Вимір переваги методики у парних запусках, перевірка встановленого підключення в робочому клієнті й запуск на приватному вебпроєкті потребують окремого доручення. Підстава для Knowledge Delta — ці результати, чинні правила про джерело пам’яті та рішення D-24.
