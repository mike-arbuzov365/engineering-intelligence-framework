01 · The problem

Chat history is not engineering memory

AI coding agents are powerful, but most agentic workflows still treat a conversation as if it were durable engineering knowledge.

  1. Previous decisions live only in a conversation that gets compacted or lost.
  2. The agent re-discovers the same files and re-derives the same conclusions every session.
  3. Local lessons never resurface before a new, similar task.
  4. Command output floods the context window without filtering.
  5. Architecture decisions and scope get mixed up with unverified assumptions.
  6. A merged PR gets treated as proof of working behavior, without evidence.
  7. Quality, privacy and token-efficiency are governed by separate, sometimes contradictory rules.
02 · The methodology

Engineering Intelligence is the system around the agent

EIF defines a governed learning flow in which a session's validated Knowledge Delta can be classified, linted, retained locally or promoted into reusable artifacts such as rules, playbooks, templates and skills.

Engineering Intelligence is versioned experience plus the methods that govern its use. It changes how the next task is prepared, executed and verified - not merely where knowledge is stored.

Methodology
Principles, ontology, authority, playbooks and evidence rules define how work is performed.
Experience
Validated facts, decisions, incidents, failure patterns and rejected approaches are retrieved before implementation.
Capability
Templates make good structure repeatable; skills make complete workflows invokable by an agent.

What “learning” means here: the engineering system externalizes validated experience into reviewed, versioned artifacts that the next session can retrieve. EIF does not train model weights, fine-tune an LLM or let an agent rewrite its own safeguards.

04 · The control plane

One governed loop, source to durable knowledge

EIF is a control plane that coordinates tools and agents without replacing them. It connects knowledge, authority, execution and evidence into a single, observable sequence.

  1. 01 · User intent

    A task or question enters the loop.

  2. 02 · Experience retrieval

    Prior validated knowledge is pulled into context before new work starts.

  3. 03 · Authority and scope

    What should happen, what actually happens, and what may be cited are kept as separate questions.

  4. 04 · Structural navigation

    An optional code graph may help find things faster. It is navigation evidence, not authority.

  5. 05 · Controlled execution

    Work proceeds under explicit scope, budgets and stop conditions.

  6. 06 · Tests and evidence

    A merged change is not treated as proof of working behavior on its own.

  7. 07 · Knowledge Delta

    What was learned is written down in the same session, not left in chat.

  8. 08 · Durable engineering intelligence

    Validated knowledge is available to the next task and the next agent.

Source files remain authority throughout. An optional structural graph, when present, is navigation evidence: it does not replace source verification.

05 · The session

A session is the unit of controlled work and learning

EIF requires relevant prior-knowledge retrieval before non-trivial work and defines preparation, controlled execution, verification and closeout as the session lifecycle.

  1. 01

    Retrieve and orient

    Read active instructions and source, then search durable knowledge for relevant lessons, failures and rejected approaches.

    Tier 1 + Tier 2
  2. 02

    Scope and prepare

    Choose a single session or an execution packet. Name the goal, evidence, constraints, budgets and stop conditions.

    Task scope
  3. 03

    Execute and verify

    Keep observations separate from assumptions, work within scope and use declared evaluators instead of completion language.

    Tier 3
  4. 04

    Close out and promote

    Record actual evidence, open work and Knowledge Delta. Retain validated learning; remove or discard ephemeral session state.

    Durable delta

Tier 3 is a checkpoint, not memory: it may contain progress, evidence labels, open questions and a draft delta, but no raw AI reasoning. It is never promoted wholesale.

06 · The evidence loop

Bounded, not autonomous

EIF includes a bounded evidence-loop contract for iterative agent work, with explicit evaluators, budgets, evidence and stop conditions. This is a methodology contract. It does not by itself prove fewer retries, higher quality, lower cost, or reliable autonomous completion.

  1. 01 · Orient

    Read current source and relevant retrieved knowledge. Record facts separately from assumptions.

  2. 02 · Define

    State the next smallest hypothesis and the observation that would confirm or reject it.

  3. 03 · Act

    Make one reversible change or run one diagnostic experiment.

  4. 04 · Observe

    Run the declared evaluator and record its actual output.

  5. 05 · Study

    Compare expected and actual results. If unsuccessful, record a concise failure signature comparable across attempts.

  6. 06 · Adapt

    Select the next action because of the observation. An unchanged failing action with no new evidence is not repeated.

Preconditions

Goal
One observable outcome.
Success evidence
What proves the outcome behaviorally.
Evaluator
Test, tool, source comparison, rubric or named human decision.
Iteration limit
Positive integer, default 5.
Remote budget
Default 0 unless explicitly authorized.
Stop conditions
Safety, ambiguity, budget or owner-only boundaries.

Exits

Pass
Only when success evidence exists.
Blocked
A stop condition is reached, the evaluator is unavailable with no adequate substitute, the iteration budget is exhausted, or the same unchanged failure signature would be attempted a third time.
Deferred
Only when the remaining work is explicitly owner-gated or outside ratified scope, with a named destination.
07 · Governed learning

From experience to reusable knowledge and skills

EIF defines a governed learning flow in which a session's validated Knowledge Delta can be classified, linted, retained locally or promoted into reusable artifacts such as rules, playbooks, templates and skills.

  1. Observe

    Real work produces evidence: a fact, incident, rejected approach, risk or repeatable method.

  2. Capture

    The session records a concise Knowledge Delta, including what remains unverified.

  3. Retro

    Closeout compares intent with evidence, extracts failure patterns and decides whether a lesson is reusable.

  4. Classify + validate

    Knowledge Ingest and Lint check artifact type, source, status, language, duplication and links.

  5. Promote

    Project-specific knowledge remains in Tier 2; a general lesson moves to Tier 1 only by explicit decision.

  6. Retrieve

    The next relevant session finds the artifact before acting, closing the learning loop.

Experience

What the system has learned

Facts, decisions, incidents, edge cases, failure patterns and lessons with provenance and lifecycle status.

Skill

How the system can act

A reusable, invokable workflow for planning, execution, review, retrieval or curation. It is versioned instructions, not hidden model behavior.

This is governed system-level learning, not autonomous self-modification. A lesson can be rejected, remain local, expire or be superseded; a local skill may specialize workflow but cannot lower framework safety rules.

08 · Optional capabilities

Three accelerators, three explicit fallbacks

Graphify, RTK and Context7 each add one bounded capability. None is the methodology itself: when one is unavailable, EIF keeps a named core path through source search, raw shell output or local documentation.

  • Data boundary: local-only for AST-based extraction; external-api only if semantic labeling is explicitly enabled.

    Degraded mode without it: the agent falls back to source search and manual browsing; no graph-level path or impact hints.

    Health: fresh/stale/unknown/diverged freshness classification; a stale or unknown graph never reports healthy. Bounded to one local version and a small synthetic fixture, not a comparative navigation outcome.

  • Data boundary: local-only.

    Degraded mode without it: shell commands run unfiltered and no reduction is recorded.

    Health: a failed required canary reports degraded, not healthy. A raw or failed proxy route is recorded as zero savings, never a positive reduction number.

  • Data boundary: external-api; queries a hosted documentation service.

    Degraded mode without it: the agent relies on local docs or training-data knowledge, which may be outdated.

    Health: declaration-only until its provider adapter passes its own session and evidence gate.

09 · Current tasks and evidence

What is bounded and observed today

Seven tasks a governed agent actually performs with this framework, each with its own evidence and boundary, not a single blanket capability claim.

  • A real wheel built from pyproject.toml, installed into a clean venv, gives a working eifctl command (init, doctor, search, render, privacy-scan, validate, version) proven through a full synthetic-task journey.

    Limitation: not published to PyPI; the full journey exercises the Claude Code adapter for its own bootstrap step.

  • An adoption preflight detects pre-existing project governance before any write and refuses to proceed without an explicit coexistence decision; coexist mode defers to existing rules instead of declaring sole authority.

    Limitation: governance detection is a content-length heuristic, not semantic; verified against one synthetic fixture plus repeated runs against one real private pilot target.

  • Offline, lifecycle-aware, schema-aware keyword retrieval surfaces relevant validated knowledge (including Ukrainian), excludes rejected/superseded results by default, and reports unparseable vs. schema-invalid vs. not-found as three distinct outcomes.

    Limitation: offline keyword/substring scoring, not semantic search; tested against small seeded indexes.

  • Work is scoped as a session or execution packet with an explicit evaluator, iteration/remote-run budgets, and a named stop condition (see the evidence loop).

    Limitation: a methodology contract, not a guarantee of fewer retries or lower cost.

  • A bundled verifier checks config/lock schema validity, manifest digests against a fresh recompute, adapter/config consistency, marker integrity, and drift between config and generated entrypoint content.

    Limitation: scoped to the bundle's own manifest, not a general-purpose file-integrity tool.

  • A full directed switching matrix (12 ordered pairs across Claude Code, Cursor, Codex and Hermes) proves exactly one active EIF block, correct destination resolution, and project-content preservation after every switch.

    Limitation: only Claude Code and Cursor are required for v0.1; Codex and Hermes are experimental-supported additions.

  • Retrieval, Knowledge Delta rendering, session-closeout rendering and generated entrypoint content have been verified in Ukrainian, config-driven per project instance.

    Limitation: does not cover an agent's own free-form conversational responses.

Bounded proof on record

  • A first bounded real-agent pilot (one model, three fixtures, six total attempts) completed with 100% task success in both baseline and EIF-governance modes. This is not a statistically powered efficiency comparison (see limitations).
  • Command-level timing evidence exists for specific mechanical operations in the framework's benchmark evidence. No claim is made about human authoring or review time.
10 · Quickstart

A synthetic walkthrough, not a release

Cloning the repository gets you the ontology, schemas, governance docs, the eifctl source package, and one reproduced vertical slice, not a stable release or a representative sample of real engineering tasks. 

python scripts/eif_init.py --framework-root . --instance-path <path> --project-name <name> --locale en

That one command initializes a separate, runnable project instance. The bundled demo then seeds and retrieves real knowledge, makes one change informed by that retrieval, verifies it with a real failing-before/passing-after test, and closes out in Ukrainian, via a config-driven locale layer, in the reference walkthrough.

No PyPI package yet. No claim about how long any of this takes a human.

11 · Limitations

What this is not, yet

  • Pre-release. v0.1 is in progress; this repository is being extracted from a private production instance. Expect gaps.
  • Not on PyPI. There is no pip install from a package index yet.
  • No quality or rework claim. No comparative study has been run; this framework makes no claim about task quality, rework rate or defect count.
  • Bounded scale. Evidence comes from one synthetic vertical slice, a three-fixture benchmark pilot, and adapter-level test suites, not a large or independently-reproduced sample.
  • Optional integrations stay optional. Graphify and RTK are never required; a stale or degraded provider is reported as such, never marketed as healthy.
  • Explicit v0.1 non-goals: hosted SaaS, an autonomous multi-agent runtime, a proprietary cloud memory service, a mandatory code-graph or shell-compression dependency, or any universal token-savings claim.
